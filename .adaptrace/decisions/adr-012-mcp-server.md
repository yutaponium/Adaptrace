# MCPサーバーは公式SDKで作り、読み取りと書き込みの提案だけを許す

> 注：2026-11-23に文言だけを修正した。決定の内容は変えていない。

## 決定

- `accordant mcp [bundle]` で、stdioのMCPサーバーとして起動する。CLIと同じパッケージに含める
- 公式の `@modelcontextprotocol/sdk` と、その入力の定義に使う `zod` を実行時の依存に追加する
- ツールは読み取り（検証、文書の一覧と取得、グラフ、影響分析、陳腐化、カンバン、Backlog.mdとの同期の計画）と、書き込みの提案（`propose_document`、`propose_update`）だけにする
- 提案のツールはファイルに書き込まない。新しい内容、差分、その変更で新しく出る問題と消える問題を返す。適用は人か、エージェント自身の編集機能で行う

## 理由

- 設計原則「ユーザーの文書を勝手に書き換えない。更新案は提示し、適用は人が決める」に合わせる。エージェントは、自分の編集機能を使えば、クライアントの承認を経てファイルに書き込める
- 提案と一緒に「変えたらどうなるか」の検証結果を返せば、エージェントが壊れた依存関係や循環依存を作る前に気づける
- プロトコルの更新に自分で追従するより、公式SDKに任せた方が確実
- 同じパッケージなら、インストールもバージョンも一つで済む

## 検討した他の案

- プロトコルを自分で実装する：依存はゼロのままだが、仕様の変更を自分で追う必要がある
- 書き込みもツールで許す：クライアントの承認に頼ることになり、設計原則から外れる
- 読み取りだけにする：エージェントが更新案を作るときに、検証結果を自分で確認する手段がない
- 別のパッケージにする：CLIだけを使う人にSDKをインストールさせずに済むが、管理するものが増える
