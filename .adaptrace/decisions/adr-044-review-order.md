# 重い指摘があるうちはClaudeのレビューだけを繰り返し、なくなってからGeminiのレビューを実行する

## 決定

- コードを変更するPRのレビューの進め方を、次のようにする。ADR-017の「2つは同時に開始する」を、初回だけにする
  1. 初回は、`/code-review` とGeminiのレビュー（skill「gemini-review」）を同時に開始する
  2. 重い指摘（正しさ、データの欠落や破損、セキュリティ、秘密情報）があれば、修正した後は `/code-review` だけを実行する。重い指摘がなくなるまで繰り返す
  3. 重い指摘がなくなったら、最後にGeminiのレビューを1回実行する
  4. 最後のGeminiのレビューで重い指摘が出たら、修正して2に戻る。軽微な指摘だけなら、修正して終える
- 初回のレビューで重い指摘がなければ、Geminiのレビューを繰り返さない
- PRの本文の「レビュー」には、実行した回数と、それぞれの指摘への採用・不採用を書く

## 理由

- 1回のレビューで重い指摘がなくなることは、まれである。修正のたびに2つのレビューを実行すると、Geminiの利用の上限（5時間ごとのクレジット）を早く使い切り、待ち時間も増える
- 別のモデルの視点は、初回と、修正が落ち着いた最後に入れれば足りる。途中の修正の確認は、Claudeのレビューで行える

## 検討した他の案

- 毎回、2つのレビューを同時に実行する（ADR-017のまま）：Geminiのクレジットが足りなくなり、2026-11-26には最後のレビューを実行できなかった
- Geminiのレビューを、最後の1回だけにする：初回の別の視点が失われ、設計の大きな問題を、修正を重ねた後で見つけることになる
