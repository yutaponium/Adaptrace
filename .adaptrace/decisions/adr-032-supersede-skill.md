# 判断の置き換えは、skillが新しい判断を作り、依存していた文書を1件ずつ利用者と決める

## 決定

- 判断の置き換えを、skill `accordant-supersede` で支援する。ADR-026の使い分けに従い、CLIに新しい機能は追加しない。依存している文書の洗い出しには、`impact` と `graph` を使う
- 範囲は、新しい判断の作成から、依存していた文書の付け替えまでとする。新しい判断がすでにあれば、付け替えから始める
- 新しい判断は、`supersedes` で古い判断を指す。古い判断は `status: deprecated` にし、本文は書き換えない。これはADR-031と同じ扱いである
- 新しい判断の理由と、検討した他の案は、利用者に尋ねて書く。推測で書かない
- 古い判断を直接指している文書ごとに、付け替える、外す、中止する、そのままにする、のどれかを利用者が決める。間接的に影響を受ける文書は変更せず、見直しの対象として報告する
- 依存関係のキーや `status` だけを変える文書の `generated` は、変えない。付け替えた文書は、新しい判断より古くなるので、`stale` で見直しの対象として示される
- `changes` で古い判断を指す変更要求は、変更せず、報告する

## 理由

- 判断を置き換えると、その判断を前提にした文書が残る。依存関係のキーを機械的に付け替えると、前提が変わったのに内容が古いままの文書が、正しく見える。文書ごとに扱いを決める必要がある
- 付け替えた文書の `generated` を変えなければ、`stale` がそのまま見直しの一覧になる。見直しは、skill `accordant-review` で進められる
- 判断の経緯は、置き換える前の判断と理由が残ってはじめて分かる。そのため、古い判断の本文は書き換えない

## 検討した他の案

- 付け替えだけを支援し、新しい判断の作成は利用者に任せる：判断を置き換える作業の多くが、利用者の手作業に残る
- 依存していた文書を、すべて新しい判断に付け替える：中止すべき作業や、関係がなくなったリスクまで、新しい判断につながってしまう
