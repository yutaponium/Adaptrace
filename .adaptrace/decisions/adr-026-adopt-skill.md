# 既存のファイルの取り込みと依存関係の作成は、Claude Codeのskillで対話しながら支援し、リポジトリで配布する

## 決定

- 既存のリポジトリのファイルをバンドルに取り込み、依存関係を張る作業を、Claude Codeのskill `accordant-adopt` で支援する
- skillは、このリポジトリの `skills/accordant-adopt/SKILL.md` に置いて配布する。利用者は、導入先のリポジトリの `.claude/skills/` か `~/.claude/skills/` にコピーして使う
- 支援する範囲は、取り込み（バンドルに移すか、代わりの文書を置くか）から、依存関係を張るまで。ガイド「既存のリポジトリにAccordantを導入する」の手順4と5に当たる
- 依存関係の候補は、エージェントが本文を読んで選び、根拠と確からしさを付けて示す。採否は利用者が決める
- 書き込むのは、利用者がファイルごとの差分を承認した後だけ。エージェントが編集の機能で書く
- skillは、AccordantのCLI（`init`、`list`、`validate`、`stale`、`impact`、`extract`、`graph`）を使う。CLIに新しい機能は追加しない
- CLI・MCPとskillは、次のように使い分ける。この使い分けは、今後のskillにも適用する
  - 新しくできるようにすること（計算、判定、材料の収集）は、CLIに作り、必要ならMCPのツールにする
  - 複数の機能を組み合わせて、利用者と対話しながら進める作業は、skillにする。skillには手順と判断の基準だけを書く
  - skillの中で新しい計算や判定が必要になったら、skillに書かず、CLIやMCPに機能として追加する
  - skillからAccordantを使うときは、MCPではなくCLIを使う。MCPサーバーを登録していない利用者でも動くため
- skillの試験は、2つの層に分ける。試験の一式は `tests/skills/accordant-adopt/` に置く
  - LLMを使わない部分は、`bun test` で毎回実行する。確認スクリプトが、期待する結果に合格を、失敗する例に不合格を出すことを確認する
  - skillの実行は、skillを変更したときに `run.ts` で手で実行する。Claude Code（`claude -p`）にskillを実行させ、確認スクリプトで判定する。結果は毎回変わるので、3回を目安に実行する
  - 試験の記録はリポジトリに入れない。合格した回数と、手順の不明な点への対応を、PRの本文に書く

## 理由

- 依存関係を張る作業は、文書の内容を読んで判断する必要がある。キーワードの一致だけでは候補を選べず、LLMに向いている
- 一方で、どの依存関係を張るかは、見直しの連鎖を決めるプロジェクトの判断である。候補を示し、利用者と対話して決める形にする
- 差分の承認を得てから書くので、設計原則6（ユーザーの文書を勝手に書き換えない）を守れる。適用は人が決めている
- skillは手順と判断の基準を書いたMarkdownで、CLIはskillに依存しない。skillがなくても、Accordantのほかの機能はすべて動く（設計原則5）。手順はガイドにも書いてあり、ほかのエージェントでも同じ手順で進められる
- リポジトリで配布すると、CLIのバージョンと手順を一緒に管理できる
- CLIとMCPの機能は、同じ入力なら同じ結果になり、どのエージェントからも使え、テストで確認できる。skillは、エージェントの判断で結果が変わり、skillの形式（Agent Skills）に対応したエージェントでしか使えない。そのため、テストで確認したい計算や判定はCLIとMCPに置き、skillは使い方の手順に限る
- LLMの動きは毎回変わるので、skillの試験をCIで毎回実行しても、結果が安定しない。費用もかかる。決まった結果になる部分だけをCIで確認し、skillの実行は変更したときに行う
- skillの実行の試験で、手順の不足が多く見つかった。たとえば、議事録から文書を起こしていない、取り込みで日時が失われる、などである。同じ条件で試し直せるように、模擬のリポジトリと確認スクリプトを残す

## 検討した他の案

- `accordant link` のようなCLIのコマンドにする：候補の選択にLLMが必要で、対話もしにくい。`--llm` で候補を出すことはできるが、採否の対話は人とエージェントの間で行う方が自然である
- MCPのツール（`link_context` など）にする：材料を返すだけなら、既存の `list_documents` と `read_document` で足りる。必要なのは、手順と判断の基準である
- 利用者の `~/.claude/skills/` だけに置く：ほかの利用者に配布されない
- 更新案を示すだけで、書き込まない：取り込みでは多くのファイルを変更するので、利用者の手間が大きい。差分の承認で十分に制御できる
