# skillの試験は変更の内容から必要度を判断し、根拠と推奨案を示してメンテナーの確認を取る

## 決定

- skillを変更するPRで、`tests/skills/run.ts` によるskillの試験を、一律には必須にしない。ADR-026の「skillを変更したときに `run.ts` で実行する。3回を目安に実行する」を、この決定で置き換える
- エージェントは、変更の内容から試験の必要度を判断する。対象のskill、回数、`--issues` を付けるかと、その根拠を推奨案として示し、メンテナーの確認を得てから実行する
- 必要度の目安は次のとおり。目安と違う判断をするときは、その理由も示す

| 変更の内容 | 必要度の目安 |
| --- | --- |
| 新しいskill | 必要。3回以上、`--issues` を付ける |
| 手順、判断の基準、書き込む範囲、使うコマンドの変更 | 必要。変更したskillで3回。修正した直後は `--issues` を付ける |
| 試験の一式（`check.ts`、模擬のリポジトリ、利用者が知っている事実）の変更 | 判定が変わり得るので、該当するskillで実行する。回数は変更の大きさで決める |
| 意味を変えない文言の修正（言い換え、表記、誤字） | 原則として不要 |
| 共通の節（「共通の書き方」）の変更 | 意味が変わるなら、影響の大きいskillを選んで実行する。意味が変わらないなら不要 |

- 試験を実行しなかった場合も、PRの本文の「レビュー」に、判断と根拠、メンテナーの確認を得たことを書く。実行した場合は、これまでどおり合格した回数と、Skill issuesへの採用・不採用を書く

## 理由

- 試験を複数回実行するのは、同じ入力でも出力がぶれるLLMの動作が、期待どおりに安定しているかを確認するためである。新しいskillや、手順と判断の基準の変更には、この確認が要る
- 意味を変えない文言の修正では、再試験で得られる情報がほとんどない。共通の節は9つのskillに同じ文面で置いているので、一律に試験すると、1回の修正で27回の実行と、その費用がかかる
- 必要度の判断を、エージェントが根拠とともに示し、メンテナーが確認することで、試験の省きすぎと、やりすぎの両方を防ぐ

## 検討した他の案

- 変更の種類ごとに、試験の要否を規則で固定する：変更の内容は多様で、規則で決めきれない。目安にとどめ、判断と確認で補う
- 共通の節の変更では、代表の1つのskillだけを必ず試験する：意味の変わらない修正にも費用がかかる。意味が変わる場合は、影響の大きいskillを選ぶほうがよい
