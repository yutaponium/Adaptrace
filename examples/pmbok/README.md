# PMBOKの文書のテンプレート

PMBOKに沿ったプロジェクトの文書を、依存関係を張った状態でそろえたバンドルです。
コピーして、自分のプロジェクトのバンドルとして使えます。
使い方の流れは、[PMBOKの文書を変更要求に合わせて更新する](../../docs/guide/pmbok.md) を参照してください。

## 2つの構成

| 構成 | フォルダ | 文書の数 | 向いているプロジェクト |
| --- | --- | --- | --- |
| 最小構成 | `minimal/` | 12 | 小さなプロジェクト。憲章、要求事項、スコープ記述書、WBS、スケジュール、コスト、リスク、変更要求など |
| 標準構成 | `standard/` | 28 | 補助計画書とベースラインまで管理するプロジェクト |

PMBOKは、プロジェクトに合わせて文書を取捨選択することを求めています。
迷ったら、標準構成から始めて、要らない文書を削除してください。

最小構成に、標準構成の文書を追加することもできます。
その場合は、追加した文書だけでなく、それに依存する既存の文書にも、追加した文書への依存関係を追加してください。
どの文書が依存しているかは、標準構成の同じファイルで確認できます。ただし、フロントマターを丸ごと写すと、最小構成にない文書を指してしまいます。追加した文書への依存関係だけを写してください。
たとえば、ビジネス・ケースを追加したら、プロジェクト憲章の `derived_from` にビジネス・ケースを追加します。
合わせないと、追加した文書が変わっても、ほかの文書が見直しの対象になりません。

## 使い方

1. 使う構成のフォルダを、プロジェクトの `.adaptrace/` としてコピーします。コピー先の `.adaptrace/` は、まだない状態にしてください。すでにあると、`.adaptrace/minimal/` のように1階層深くコピーされます

   ```bash
   cp -r <Adaptraceをcloneしたフォルダ>/examples/pmbok/minimal /path/to/my-project/.adaptrace
   ```

2. `index.md` の見出しを、プロジェクトの名前に書き換えます。`log.md` の日付も、コピーした日に書き換えます
3. 文書を書いたら、フロントマターに `generated` を追加し、書いた人と日時を記録します。`generated` がない文書は、最終更新が分からないので比べられません。`adaptrace validate` が警告します。見直して変更が要らなかったときは、`generated` を変えずに、`verified: { by, at }` に見直した人と日時を記録します

   ```yaml
   generated: { by: human:sato, at: 2026-11-18T10:00:00+09:00 }
   ```

4. 要らない文書は削除します。その文書を指している依存関係は、削除した文書の依存先に付け替えます。たとえば、アクティビティ・リストは、WBSとスケジュール・マネジメント計画書に依存しています。アクティビティ・リストを削除したら、資源要求事項と所要期間見積もりは、アクティビティ・リストの代わりに、この2つに依存させます。付け替えないと、上流の変更が下流に伝わらなくなります。フォルダの `index.md` からも、削除した文書へのリンクを削除します。`adaptrace validate` で、削除した文書を指したままの依存関係とリンクを確認できます

## 記入例

要求事項、受け入れ基準、意思決定、前提条件、マイルストーン、リスク、変更要求は、1件を1ファイルにします。
それぞれのフォルダには、記入例を1件だけ置いています。1件目は、記入例を書き換えて使ってください。記入例のまま残すと、`list` や `estimate` の件数に含まれます。

2件目からは、`examples/pmbok/` にある記入例をコピーして作ります。書き換えた1件目をコピーする場合は、`generated` と、変更要求の `received_at` を必ず書き換えてください。古い日時のままだと、見直しの判断を誤ります。作った文書は、フォルダの `index.md` にも追加します。**作ったら、記入例を指している下流の文書にも、その文書への依存関係を追加してください。** 追加しないと、その文書を変えても、下流の文書が見直しの対象になりません。

| 追加した文書 | 依存関係を追加する文書（標準構成） | キー |
| --- | --- | --- |
| 要求事項 | 受け入れ基準、意思決定、スコープ記述書 | 受け入れ基準とスコープ記述書は `derived_from`、意思決定は `depends_on` |
| 受け入れ基準 | スコープ記述書、品質尺度 | `derived_from` |
| 意思決定 | WBS、リスク | `depends_on` |
| 前提条件 | スコープ記述書、所要期間見積もり、リスク | `depends_on` |
| マイルストーン | スケジュール・ベースライン | `depends_on` |
| リスク | コスト見積もり | `depends_on` |

関係のない文書には、追加しなくて構いません。たとえば、受け入れ基準は、それが基準とする要求事項にだけ `derived_from` を張ります。
最小構成では、この表のうち、最小構成にある文書だけが対象です。

変更要求の記入例（`change-requests/cr-001.md`）には、`requested_by` と `received_at` をコメントで入れています。
変更要求を受け付けたら、`#requested_by:` と `#received_at:` の行頭にある `#` を削除して、値を書き換えてください。説明のコメント行（`# ` で始まる行）は、そのまま残すか削除します。`adaptrace progress` が、見直しのもれを確認するときに使います。

## 依存関係の考え方

- 依存関係は、下流の文書から上流の文書へ張っています。「上流が変わったら、下流を見直す」向きです
- リスクはスケジュールに依存しています。逆向きには張っていません。両方向に張ると、循環依存になるためです
- プロジェクトマネジメント計画書は、標準構成では補助計画書とベースラインに依存しています。最小構成では、スコープ記述書、WBS、スケジュール・ベースライン、コスト見積もりに依存しています。どれかが変わると、計画書全体の見直しが一覧に出ます
- 前提条件は、標準構成では、スコープ記述書、所要期間見積もり、リスクから依存されています
- 変更要求は、どの文書にも依存していません。承認されたら、変更要求が直接変える文書の `derived_from` に、変更要求を追加します

## 型の名前

`type` の値は、[PMBOKのガイド](../../docs/guide/pmbok.md#型を決める) の表に合わせています。
作業（`Task`）は、必要な場合だけ使う型なので、テンプレートには含めていません。
Adaptraceの型の一覧は、まだ確定していません。今後、型の名前を変える可能性があります。

## PMBOKについて

PMBOKは、Project Management Instituteの登録商標です。
このテンプレートに含めているのは、文書の名前と依存関係だけです。PMBOKガイドの本文は含めていません。
